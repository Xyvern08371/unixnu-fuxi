## M4 完成：内核交接链路打通（2026-10-18）

探针 v37 在真机上显示：

```
M4
DTB   0X00000000XXXXXXXX      ← 指向驱动的内嵌设备树
MAGIC 0XD00DFEED
DT OK
BUILTIN
CFG   0X0000000000000009
```

这意味着以下四件事同时成立：

| 能力 | 实现方式 |
|---|---|
| 关闭中断 | `msr daifset, #0xf` |
| 换用自己的栈 | 退出 Boot Services 前分配 64KB，跳转前 `mov sp` |
| 按内核约定传参 | `x0` = 设备树物理地址 |
| 跳转到新入口 | `br x0`（通过函数指针，等价于内核入口） |

## 设备树拿不到的问题（已解决）

实测这版固件的 EFI 配置表里**没有设备树**（9 个条目都不是 DT，按 GUID 和按魔数都找不到）。
正确时机也确认了：驱动入口时配置表还没齐，要到 BDS 阶段才完整——所以扫描必须在
`ExitBootServices` 之前再做一次。

最终方案：**把真机导出的设备树编进驱动**。

```
rom/device/fuxi_runtime.dtb   (818 KB)
    ↓ CI 里跑 tools/gen_dtb_blob.py
loader/fuxi_dtb.c             (5 MB 源码)
    ↓ 编译进 FuxiProbe
驱动自带一份有效设备树 → 交给"内核"（x0）
```

固件卷是 LZMA 压缩的，所以固件只增大 86KB（6508544 → 6594560）。

## 至此具备的能力（最小引导器）

```
1. 从固件启动、初始化显示、拿到帧缓冲
2. 退出 Boot Services，进入真正的裸机环境
3. 在自己的环境里输出文字（自带点阵字体）
4. 关中断、换栈、传设备树、跳转到任意入口
```

这四步合起来就是一个**能启动操作系统的最小引导器**。后续接任何内核（Linux、
或我们想尝试的 XNU）都是在第 4 步之后换一个 payload。
