### 2. 加载器（M7 前半）
loader/ 下新增：

| 文件 | 作用 |
|---|---|
| XnuBoot.c | 解析 payload、按段拷贝、填 boot_args、跳转 |
| XnuLoad.c | 从 EFI_BLOCK_IO 读 payload（本固件无块设备） |
| XnuFv.c | **从固件卷 RAW section 读 payload（成功）** |
| XnuMem.c | 用 AllocatePages 拿内核内存并改写 ADT 的 dram-base |
| XnuMmu.c | 自己建页表（试过，会让 UEFI 崩 → 已停用） |
| XnuUfs.c | 直接读 UFS（MMIO 未映射，崩） |
| xnu_jump.S | 清缓存、关 MMU、跳 __start |

### 3. 实测走通的链路

`
UEFI 启动
  → 探针驱动执行
  → 从 FV RAW section 拿到 payload（15.8MB）
  → AllocatePages 拿到 0x98000000（4GB 以下）
  → 拷贝内核段 → SEGS DONE
  → 改写 ADT 的 dram-base/size → ADT PATCHED = 2
  → 填 boot_args → BOOTARGS
  → 清缓存、关 MMU、跳 __start
  → 之后屏幕无变化（XNU 早期死掉，无输出）
`

### 4. 踩过并解决的坑

| 坑 | 结论 |
|---|---|
| EFI 内嵌 15.8MB 内核 | 模块过大，UEFI 加载崩 → 改用 FV RAW section |
| 这版固件无块设备驱动 | EFI_BLOCK_IO 枚举为 0 |
| 直接读 UFS MMIO | 0x1d84000 未映射 → 同步异常 |
| ADT 硬编码 phys_base=0x100000000 | UEFI 页表未映射 → external abort |
| 接管 TTBR0 自己建页表 | 会把 UEFI 的 MAIR 语义搞乱 → 立刻崩 |
| 屏幕日志行距 24 < 字高 48 | 文字叠在一起 |
| 绘制未做缓存回扫 | 少量像素留在 cache，屏幕上没有 |

## 明天要做的

### 第一步：跳转自测
在跳 XNU 之前加一个模式：跳到我们自己的汇编桩，它用 MMU-off 状态
直接往帧缓冲写一行 "JUMPED OK"。

- 能写出来 → 跳转机制 OK，问题在 XNU 侧
- 写不出来 → 跳转机制有问题（寄存器/MMU 状态）

### 第二步：按结果分头处理

**若是 XNU 侧**：
- 核对 boot_args 每个字段（Revision/Version/virtBase/physBase/memSize/
  topOfKernelData/deviceTreeP/deviceTreeLength）
- 核对 ADT 是否满足 start.s 早期需求（/chosen、cpus、memory-map）
- 参照 ios-sweet 的 NOTES.md，看他们 boot 早期崩过哪些点

**若是跳转侧**：
- 检查 SCTLR 关闭顺序、字节序、栈对齐
- 参考他们的 loader.c 最后几行逐步对齐
